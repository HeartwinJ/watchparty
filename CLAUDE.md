# CLAUDE.md

Personal fork of [howardchung/watchparty](https://github.com/howardchung/watchparty): a site for watching videos together with synced playback, chat, screen share and file share. The goal is to add my own features and self-host it for personal use, not to run the public watchparty.me service.

## Git & PR rules (important)

- `origin` = `HeartwinJ/watchparty` (my fork, **public** repo, so never commit secrets). `upstream` = `howardchung/watchparty`, **fetch-only** (its push URL is deliberately disabled).
- **Never push to upstream and never open PRs/issues against `howardchung/watchparty`.** Because this is a fork, `gh pr create` may default to the parent repo, so **always** pass `--repo HeartwinJ/watchparty --base master`.
- Work on a feature branch (`feat/…`, `chore/…`, `fix/…`), open a PR to `master` on the fork, and merge only after CI is green.
- Before opening a PR, run `npm run format:check && npm run check && npx vite build`.
- **Keep the docs in step with the code, in the same PR.** Any change to a feature or to behaviour that users, operators or future contributors need to know about must update the relevant docs:
  - `README.md`: the feature list, configuration table and deployment notes.
  - `DEPLOY.md`: setup, upgrades and backups.
  - `.env.example` and `server/config.ts` comments: new or changed settings.
  - `CLAUDE.md`: architecture, events and API contracts, data and gotchas.
  - `src/components/App/README.md`: the room page.

  Pure bug fixes, refactors and small internal changes don't need doc updates unless they change documented behaviour. A PR that changes documented behaviour without updating the docs isn't ready to merge.

- The fork has diverged heavily from upstream (paid features, accounts and Postgres/Redis removed; SQLite, password auth, redesigned UI, AIOStreams, compose stack with cloudflared). Cherry-pick specific upstream fixes rather than merging. Keep this file and `README.md` (feature list) up to date as features land.

## Commands

```bash
npm install            # node_modules is not checked in; run this first
npm run dev            # backend on :8080, restarts on changes under server/ (node runs .ts directly)
npm run ui             # Vite dev server for the React client (run in a second shell)
npm run typecheck      # client typecheck (src/tsconfig.json)
npm run typecheckServer# server typecheck (server/tsconfig.json)
npm run build          # vite build -> build/, plus both typechecks
npm test               # Vitest, run once (npm run test:watch for watch mode)
npm run check          # both typechecks + tests
npm run format:check   # Prettier check (CI enforces it); npm run prettier to fix
npm start              # production: serves the API and build/ from one process
```

- CI (`.github/workflows/nodejs.yml`) runs on PRs and pushes to `master`: format check, both typechecks, unit tests and the Vite build.
- Tests use **Vitest** (+ `@testing-library/react` for hooks/components) and live next to the code as `*.test.ts(x)`. `server/**` tests run in the `node` environment and `src/**` tests in `happy-dom` (projects are defined in `vite.config.ts`). Add tests for new logic, especially pure helpers (parsers, sync math, stream ranking) and socket handlers.
- Node 24+ is required. The server runs TypeScript directly with no compile step, so server code must use only **erasable** TS syntax (`erasableSyntaxOnly`): no `enum`, no `namespace`, no constructor parameter properties. Relative imports must include the `.ts` extension (`import x from "./utils/db.ts"`).
- `typescript` is v7 (the native/Go compiler).

## Architecture

**Server (`server/`)**: Express 5 + Socket.IO (websocket transport only).

- `server.ts`: HTTP routes (`/createRoom`, `/generateName`, `/youtube`, `/youtubePlaylist/:id`, `/proxy/*`, subtitles, `/iceServers`, `/ping`), Socket.IO setup, the in-memory `rooms` Map (`loadRoom(key)` returns a room from memory or loads it from SQLite), owner/guest auth wiring (`createRoomAuth`, `admitRoomSockets`), the 1s save loop (`persistRooms` in `roomLifecycle.ts`: rooms with people get `lastUpdateTime = now` and are saved; empty rooms aren't saved and keep their time, and are unloaded once idle and loaded for 8h), the inactivity sweep (`sweepInactiveRooms`, at startup and every 24h, unref'd), `DELETE /rooms/:roomId` (`requireOwner`, Home's recent rooms) and graceful shutdown (SIGTERM/SIGINT save every room and close the DB). It also serves `build/` as a single-page app (SPA) fallback. Single process, no sharding.
- `room.ts`: the `Room` class. **Each room is its own Socket.IO namespace** (`/roomId`). Client→server events are named `CMD:*` and registered with the wrapped `on(...)` helper in the constructor, which catches errors so one bad message can't crash the process. Room state (video, timestamps, playlist, chat, roster) lives in memory. `serialize()`/`deserialize()` handle persistence, and `saveRoom()` writes the room to SQLite. Screen/file share is P2P WebRTC, signaled via `CMD:joinScreenShare`/`CMD:leaveScreenShare`/`signalSS`. `CMD:videoMeta {url, meta: VideoMeta|null}` attaches AIOStreams metadata (`{source:"aiostreams", type, id, imdbId, season, episode, title, episodeTitle, poster, bingeGroup}`, validated in `videoMeta.ts`, ≤ 4 KB) to the current video only if `url` still matches; it's serialized with the room, cleared by every host change and broadcast as `REC:videoMeta` (also sent on connect). `CMD:playbackIssue {reason}` (≤ 200 chars, rate limited per user and per room) is broadcast as `REC:playbackIssue {userId, name, reason}`. `CMD:playlistAdd` also accepts `{url, name?, img?, meta?}`; queued `meta` is restored when the item plays. `CMD:roomSettings (patch: Partial<RoomSettings>)` updates the room-wide settings (`RoomSettings = {title, readyCheck, nextEpisodeOffset}` in `global.d.ts`, default `{title: "", readyCheck: false, nextEpisodeOffset: 25}`): validated/normalized in `roomSettings.ts` (title trimmed, control/bidi characters stripped, ≤ 60 chars, `""` = generated name; offset an integer clamped to 5–120 s), no-op patches ignored, ≤ 20 changes per 10 s per room. The full settings are broadcast to everyone as `REC:roomSettings (settings)` (also sent on connect) and serialized with the room (old rooms get the default). After 1.5 s without further edits by the same person, each setting that ended up different is announced as a chat line `{cmd: "roomSettings", msg: JSON of the one changed key}` (described by `describeChatCommand`). **Ready check** (`readyCheck.ts`, pure state machine; Room applies its effects): clients send `CMD:readyState {ready, buffering?, time?}` when it changes; when `roomSettings.readyCheck` is on (clients only report then) a debounced stall (`buffering`) or a join mid-play (not a quick reconnect) pauses everyone (`REC:pause` without actor, plus `REC:seek` to the stalled viewer's `time`) and broadcasts `REC:readyCheck {active, waitingFor: clientIds, deadline, reason, trigger}`; it resumes (`REC:play`) when everyone waited for is ready, has left or never reported (5 s grace), after 30 s, or on `CMD:readyCheckSkip`. Manual play/pause and host changes cancel it; turning the setting off during a check ends it and resumes. The ended state carries `outcome` (`ready|timeout|skipped|cancelled`) and `actorId`; it's sent on connect too. Never for screen/file share Next episode(`nextEpisodeController.ts`): `CMD:nextEpisode {action:"offer", url, time, duration}` (a player within `roomSettings.nextEpisodeOffset` s of the end of an episode; the first one per video counts) makes the server resolve the next episode + stream (`addons/nextEpisode.ts`, via `Room.nextEpisodeResolver`, set in `server.ts`; null without AIOStreams). `{action:"cancel"|"playNow"}` act for the whole room; `{action:"ended", url}` is sent when a player ends. The server broadcasts `REC:nextEpisode` (`NextEpisodeState` in `global.d.ts`: `none` / `offered {next: {meta, thumbnail}, startAt}` / `cancelled {by}` / `starting {next, by}` / `failed {next|null}`; never a URL; the current card is sent on connect). It starts the next episode on Play now, on the first `ended`, or when the room time (max `CMD:ts`) reaches `startAt` (the reported duration); a queue or loop withdraws the card, seeking back before the window withdraws it, every host change resets it. **Owners vs guests in the room:** the namespace auth middleware sets `socket.data.owner` (and `socket.data.guestId` for guests). Owner-only commands (`CMD:roomSettings`, `CMD:roomPassword`, `CMD:kickUser`, `CMD:deleteChatMessages`, `CMD:deleteRoom`) are wrapped in `ownerOnly(...)`, which answers anyone else with an `errorMessage` and does nothing (fail-closed: a socket without `data.owner === true` is never an owner, so socket tests that need owners must set it in a `new_namespace` middleware). Everything else (playback, video, queue, chat/reactions, subtitles, screen/file share, ready check, next episode) is open to guests too. **Room password** (`roomAccess.ts`, `Room.access`): `{password, enabled, epoch, revoked[]}`, serialized with the room as `access` (plaintext; a low-value secret owners read back). New rooms, and rooms loaded without `access`, get a generated readable password (`makeRoomPassword()` in `moniker.ts`, e.g. `otter-maple-42`, picked with `crypto.randomInt`) that's required; a legacy room is saved right after it gets one. `CMD:roomPassword {action:"regenerate"} | {action:"set", password (4–64 chars, trimmed, no control chars)} | {action:"enable", enabled}`: a new password or turning it on bumps `epoch` (all guest grants die, `revoked` is cleared), disconnects every connected guest with `REC:accessRevoked`, saves the room and posts a chat line `{cmd:"roomPassword", msg:"changed"|"on"|"off"}` (never the password). Turning it off keeps guests. `REC:roomAccess` (`RoomAccessInfo` in `global.d.ts`) goes to each socket on connect and after every change: owners get `{enabled, password}`, guests only `{enabled}`. **Never put the password in anything a guest receives** (`REC:roomSettings`, roster, chat, logs). **Deleting a room**: `CMD:deleteRoom` (owners only) and `DELETE /rooms/:roomId` both call `Room.deleteRoom(by)`: it deletes the room row and its `history` rows (`deleteRoomData`), emits `REC:roomDeleted {by: PlaybackActor|null}` (`RoomDeletedInfo`), disconnects every socket, `destroy()`s the Room (after which `saveRoom`, host changes and late async work are no-ops, so nothing recreates the namespace) and calls `Room.onDeleted` (server.ts removes it from `rooms`). The link then 404s like any unknown room. **Automatic video changes**: `cmdHost(null, url, meta, {via: "queue"|"nextEpisode", name?})` (queue advance, next episode with no actor) posts a chat line without a person, `{id: "", cmd: "nowPlaying", msg: JSON {via, title}}` (`nowPlaying.ts`: title = videoMeta title + `S01E03`, else `#wp-name=`, else the queue item's name) or `{via, url}` when there's no readable title; changes someone chose keep the `{id, cmd: "host", msg: url}` line. `CMD:kickUser {userToBeKicked: clientId}`: a guest's `guestId` is added to `access.revoked` (bounded to 200, persisted), and every socket with that guestId gets `kicked` and is disconnected; kicking an owner only disconnects them.
- `roomLifecycle.ts`: `persistRooms` (the save loop), `sweepInactiveRooms` and `parseMaxIdleDays` (pure enough to test with fake rooms).
- `config.ts`: **every server env var with its default and a comment**. Add new server config here.
- `utils/`: `db.ts` (SQLite via built-in `node:sqlite`; add schema changes to `MIGRATIONS`, tracked with `PRAGMA user_version`), `auth.ts` + `session.ts` (instance password, HMAC-signed `wp_session` cookie, login rate limit), `guestToken.ts` + `roomAuth.ts` (room guests: signed `wp_guest` grants, `requireMember`/`requireOwner`, `/rooms/:roomId/info|join`, Socket.IO admission), `iceServers.ts` (Cloudflare TURN credentials, STUN fallback), `youtube.ts` (small `fetch` client for the YouTube Data API), `ssrf.ts` (guards the proxy), `moniker.ts` (random room/user names from `words/`). Optional integrations are no-ops when their env var isn't set; keep it that way.
- `addons/`: AIOStreams + Stremio addon integration. `routes.ts` (`createAddonServices` (shared clients/caches, also used by rooms) + `createAddonRouter`, mounted in `server.ts`), `nextEpisode.ts` (next episode + stream choice for the room's card), `streamParser.ts` (pure parser/classifier/ranker for AIOStreams results), `catalog.ts` (Cinemeta + Anime Kitsu search/meta/next episode), `subtitles.ts` (OpenSubtitles v3), `aiostreams.ts`, `cache.ts` (`TtlCache`: TTL + LRU + in-flight de-dupe), `http.ts` (`fetchJson` with timeout/size limit and URL-free `AddonError`s, `createRedactor`), `ids.ts` (param validation). Public addons are fetched through `safeFetch`. The AIOStreams host uses plain `fetch`, because it's owner-controlled and may be on a LAN.
- **Addon API** (all `requireMember`, so room guests can use them. Every route returns `503 {error:"aiostreams_not_configured"}` without `AIOSTREAMS_MANIFEST_URL`, `400 {error:"invalid_params"}` for a bad type/id, and `502 {error:"upstream_error"|"upstream_timeout"}` when an upstream addon fails). `:type` is `movie|series|anime`. `:id` is `tt123`, `tt123:S:E`, `kitsu:123` or `kitsu:123:E`.
  - `GET /addon/search?q=` (1–100 chars) → `{movies, series, anime}: SearchItem[]`, with `SearchItem = {id, type: "movie"|"series", name, year: number|null, poster: string|null}`. Up to 20 per group, cached 1h. One failing source just gives an empty group.
  - `GET /addon/meta/:type/:id` → `Meta = {id, type, name, year, releaseInfo, poster, background, logo, description, runtime, genres[], imdbId, seasons: [{season, episodes: Episode[]}]}`, with `Episode = {id: "tt..:s:e"|"kitsu:N:e", season, episode, title, released, thumbnail}`. Movies have `seasons: []`. Specials (season 0) come last. An episode id is accepted and its base id is used. 404 `{error:"not_found"}` for unknown ids. Cached 1h.
  - `GET /addon/streams/:type/:id[?bingeGroup=]` → `{streams: StreamDTO[], counts: {direct, "convert-light", "convert-heavy", unlikely}, total}`. Sorted by tier, then score, then AIOStreams order, capped at 60 (`counts`/`total` cover everything playable). Torrent-only results are dropped. Kitsu ids are always queried as `anime`. Raw results are cached 10 min per id. `bingeGroup` adds +200 to matching streams' score (within their tier); use it for the next episode. `StreamDTO = {url, name, title, filename, resolution, sizeBytes, bitrateMbps, durationSec, source, remux, videoCodec: "h264"|"hevc"|"av1"|"vp9"|"vc1"|"mpeg2"|"mpeg4"|null, bitDepth: 8|10|null, hdr: string[], audio: ("aac"|"opus"|"mp3"|"flac"|"ac3"|"eac3"|"dts"|"dts-hd"|"truehd"|"atmos"|"pcm")[], languages: string[] (flag country codes, "multi", "dubbed"), container: "mkv"|"mp4"|...|"other:<ext>"|null, cached: boolean|null, service, addon, indexer, releaseGroup, bingeGroup, tier, reasons: string[], score}`. `url` is the AIOStreams playback URL (307s to the debrid CDN, which allows CORS + range requests).
  - `GET /addon/subtitles/:type/:id` → `[{id, lang (ISO 639-1 where known, e.g. "en", "pt-BR"), label ("English", "English 2"), url}]`. `SUBTITLE_LANGS` languages come first. Kitsu ids are mapped to the IMDb episode via Kitsu meta, or give `[]`. The SRT URLs send CORS `*`, so the browser fetches them directly.
  - `GET /addon/next/:type/:id` → `{next: Episode|null}`. Null for movies, the last episode, unknown ids, or a next episode that hasn't aired yet.
  - Tiers (guesses only; the client still probes the real tracks): `unlikely` = REMUX, > 40 Mbps, > 40 GB, unsupported container (avi/iso/m2ts/...), VC-1/MPEG-2/XviD video, or only DTS/DTS-HD/TrueHD/PCM audio. Otherwise `convert-heavy` = HEVC or 10-bit H.264. Otherwise `convert-light` = audio only AC3/EAC3/FLAC, MPEG-TS, or unknown video/audio codec. Otherwise `direct` = H.264/AV1/VP9 + AAC/Opus/MP3 (MKV stays direct with a note). Score: 1080p > 1440p > 720p > 4K, cached +50, a sane bitrate (2–20 Mbps) +20, WEB-DL +10.
- **Never show AIOStreams playback URLs** in the UI or logs: the picker hosts them with a readable name in the URL fragment (`withDisplayName` in `components/App/logic/media.ts`), and every title helper (`getMediaDisplayName`, `shortMediaTitle`) prefers it. `src/components/App/noUrlLeak.test.tsx` guards this.
- **History** (`utils/history.ts`, `utils/historyRoutes.ts`): each `Room` has a `HistoryRecorder` that writes the current item on `CMD:pause`/`CMD:seek`, right before every host change (the outgoing item), on `CMD:videoMeta` (re-keys a URL row to the title/episode) and every 30 s while playing (from the room's 1 s timer). Positions under 10 s, live streams, screen/file shares and empty videos aren't recorded. Clients send `CMD:duration` (seconds; on media change and every 30 s); an item is finished at ≥ 90 % of it or when `CMD:playlistNext` says it ended. Titles come from `videoMeta` (title + `S02E04 · Episode title`), the `#wp-name=` display name, the queue item's name, the YouTube Data API, or a short safe name (file name or host), never the raw URL. Routes (`requireOwner`; guests never see history): `GET /history?limit=` (default 50, max 200) → `[{id, roomId, kind: "aiostreams"|"youtube"|"url", title, subtitle, poster, position, duration, updatedAt, finished, group}]` (no URLs; `group` = same title, for deduping series), `DELETE /history/:id` → 204/404, `POST /history/:id/resume` → `{roomId}` (new room via `createNewRoom()` + `Room.preloadVideo(url, meta, position)`, paused; finished items restart at 0; the entry moves to the new room). Home's `ContinueWatching` shows the newest entry per `group` if it isn't finished.
- **Auth (owners and room guests)**, `utils/auth.ts` + `utils/roomAuth.ts`, wired in `server.ts`. With `APP_PASSWORD` blank everything is open and everyone is an owner (room passwords are ignored).
  - **Owner** = a valid instance session (`wp_session`, from `POST /login`). Owners can do everything: Home, history, create rooms, enter any room, manage rooms.
  - **Guest** = holds a valid grant for one room, from `POST /rooms/:roomId/join {password?}` (the room's password, or none while it's off). A guest can only use that room: no Home, history, room creation or other rooms, and no room management (see `room.ts`).
  - **Guest cookie** `wp_guest` (`guestToken.ts`): httpOnly, SameSite=Lax, Secure when `req.secure`, Path=/, Max-Age = the latest grant's expiry. Value `g1.<base64url(JSON [[roomId, epoch, guestId, expiresAtMs], ...])>.<HMAC-SHA256>`, up to 8 grants (the ones expiring first are dropped), each valid 30 days. The MAC key is `deriveGuestKey(secret)` (HMAC of a fixed label with the session secret), never the session secret itself, and the format can't parse as a `wp_session` token (or vice versa). A grant counts only while it's unexpired, its room exists, its `epoch` equals the room's `access.epoch` and its `guestId` isn't in `access.revoked`.
  - **Routes**: public: `/ping`, `/session`, `/login`, `/logout`, `GET /rooms/:roomId/info` (→ `{title, passwordRequired}` or 404; 120/10 min per IP), `POST /rooms/:roomId/join` (→ `{ok:true}` + cookie; 401 `invalid_password`, 403 `kicked` (this browser's grant for the room is revoked; until the password changes), 404 `not_found` (counts against the IP), 400 bad id, 429 `{error:"rate_limited", retryAfter}` after 10 failures per IP or 30 per room in 10 min; owners get `{ok:true}` without a cookie; constant-time comparison), static assets and the SPA fallback. **`requireOwner`**: `/createRoom`, `/history*` (and anything that lists or creates rooms). **`requireMember`** (owner or any valid guest grant): `/iceServers`, `/subtitle/:hash`, `POST /subtitle`, `/downloadSubtitles`, `/searchSubtitles*`, `/youtube`, `/youtubePlaylist/:id`, `/addon/*`, `/generateName`, `/proxy/*`. New API routes must pick one of the two (owner-only unless the room page needs it).
  - `GET /session` → `{authenticated (owner), authRequired, guestRooms: [roomId without slash]}`.
  - **Socket.IO** (`admitRoomSockets`, registered before any room exists): the main namespace admits owners only; a room's namespace admits owners, guests with a valid grant for that room, and anyone while the room's password is off (except a browser whose grant for it was revoked). Refusals are `connect_error` "unauthorized". The engine middleware only loads the room from SQLite (`loadRoom`) so the namespace exists.

**Client (`src/`)**: React 19 + Vite 8 + Mantine 9, with a tiny hand-rolled router (`router.ts`).

- `index.tsx`: routes via `useRoute()` from `router.ts` (`/` → `Home`, `/create` → `Create`, `/watch/:roomId` → `App`, anything else → `StatusPage/NotFound`), wrapped in `components/AuthGate`, which calls `GET /session` on load and picks a view with `authView(state, roomId)` (`utils/auth.ts`, pure, tested): owners see everything; on `/watch/:roomId` a guest of that room sees the room, anyone else gets `RoomJoinScreen` ("Join <title or pretty name>", room password field, inline errors, 429 countdown, "Owner? Log in"; joins by itself when the room's password is off or the link carried `#pw=`); every other page needs the instance login card (`POST /login`, with "Have a room password? Join the room" on room pages). A `#pw=<password>` fragment is read once and removed with `history.replaceState` before anything renders (`takePasswordFromHash`). A 401 from any API call or a socket `connect_error` of `"unauthorized"` sends owners to the instance login and guests back to the room password screen. `AuthContext`/`useAuth()` exposes `authRequired`, `role` (`"owner"|"guest"`), `logout()` ("Log out" is in the room's ⋯ menu and the home `AppBar`, owners only) and `roomAccessLost(roomId, reason)` (used by `useRoom` for `kicked` and `REC:accessRevoked`). Guests get no Home link (the logo isn't a link), no "Leave room"/"Log out", no room-wide settings (a note instead), no remove-person menu, and invite links without the password. A 404 from `/session` is treated as "no auth". Use `navigate()` from `router.ts` for client-side navigation.
- Non-room pages: `Home` (start a room, paste a link → `createRoom({video})`, "Continue watching" from the server history (`ContinueWatching.tsx`, `utils/history.ts`), recent rooms from `utils/recentRooms.ts`, last 8 in `localStorage`), `AppBar` (brand + ⋯ menu), `StatusPage` (centred card for create/not-found/loading/error/login), `Brand` (logo), `Avatar` (`UserAvatar`/`AvatarStack`; colours are `--wp-avatar-1..8` picked by hashing the user id). `utils/rooms.ts` has `createRoom()`, `prettyRoomName()` and `roomDisplayName(roomId, title)` (the room-settings title when set; used by the top bar, the tab title and recent rooms, which store it as `roomTitle`).
- `components/App/` is the room page: `App.tsx` is the layout (desktop grid with a resizable/collapsible sidebar; phone stack with a bottom sheet) and `hooks/useRoom.ts` composes `useRoomSocket`, `usePlayer`, `useConvert`, `useShare`, `useChat`, `usePlaylist` and `useSubtitles`. The shell views are in `components/App/shell/` (top bar, Chat/Queue/People panels, settings modal), cross-view UI state in `ui/RoomUi.tsx` (`useRoomUi()`: picker, sidebar, chat overlay, settings) and toasts in `ui/toast.tsx` (use `toast()` instead of alert UI). Pure logic (sync math, media classification, chat updates, playlist decisions, SDP tweaks, sidebar width, sheet snapping) is tested. Socket events are typed in `components/App/socketEvents.ts`; emit through `room.cmd.*`, never raw strings. **See `components/App/README.md` before changing it.** `Player.ts`, `HTML.ts` and `YouTube.ts` abstract the video players. Supported sources: YouTube, direct URLs, HLS (hls.js, lazy), DASH (dash.js, lazy), screen share and file share (P2P WebRTC only, optional in-browser transcoding via mediabunny, lazy). The emoji picker (emoji-mart) is lazy too.
- `config.ts`: client `VITE_*` env vars (only `VITE_SERVER_HOST`). `utils/api.ts` `serverPath` decides where the client sends requests: `VITE_SERVER_HOST`, or `hostname:8080` in dev, or the same origin in prod.
- **Always call the server through `apiFetch()` (`utils/api.ts`)**, never bare `fetch`: it sends `credentials: "include"` (the dev client runs on a different port) and handles 401s. URLs on other origins go through plain `fetch` without credentials. The room socket uses `withCredentials: true`.
- `utils/iceServers.ts` `getIceServers()`: fetches `GET /iceServers` once (cached 1h in memory, failures not cached) for screen/file share, falling back to Cloudflare STUN.
- Components are in `src/components/<Name>/<Name>.tsx`, with CSS modules where styling is needed.
- **Design system:** `src/theme/tokens.css` defines all `--wp-*` CSS variables (colours, type, spacing, radii, shadows, z-layers, motion) and `src/theme/theme.ts` maps them onto Mantine 9 (copper `primaryColor`, dark-only, `autoContrast` so filled copper buttons get dark text). Use the tokens in CSS modules; never hard-code colours. Copper is the only accent. Status colours are `--wp-success`/`--wp-warning` (yellow)/`--wp-danger` (rose-red).
- `global.d.ts` (repo root) has types shared by client and server (`User`, `ChatMessage`, `RoomState`, etc.). Update it when you change data sent over the socket.

**Data**: one SQLite file, `$DATA_DIR/watchparty.db` (default `./data`, gitignored, WAL mode). Tables: `rooms` (roomId, data JSON, lastUpdateTime, createdAt; every room persists), `subtitles` (uploaded/downloaded subtitles, gzipped, 24h sliding expiry), `subtitle_offsets` (room-wide subtitle offset per video, keyed by `subtitleOffsetKey()` in `server/utils/subtitleOffset.ts`) and `history` (watch history / continue watching: one row per room + item, `itemKey` = `subtitleOffsetKey()`, with title/subtitle/poster/videoMeta, position, duration, finished, updatedAt, capped at 200 rows; the `url` column is server-only and must never be returned by an API). The schema lives in `server/utils/db.ts`. **Room lifetime:** a room's `lastUpdateTime` only moves while people are in it (loading it for a join screen or `/rooms/:id/info` doesn't count; `loadRoom` passes the stored time to the Room). Rooms whose `lastUpdateTime` is older than `ROOM_MAX_IDLE_DAYS` (default 60, `0` disables) are deleted with their `history` rows at startup and daily, unless they're loaded with people in them (or were loaded in the last 10 min); `subtitle_offsets` are per video, so they stay. Only the count is logged. Owners can also delete a room right away (see `room.ts`). In the compose stack the `backup` sidecar writes nightly consistent copies to `data/backups/` (see `DEPLOY.md`); otherwise back up by copying `data/` while the app is stopped. There's no Postgres or Redis.

## Configuration / self-hosting notes

- Copy `.env.example` to `.env` (gitignored). Both server and Vite load it via `loadEnvFile()`.
- Client env: only `VITE_SERVER_HOST` (optional). Firebase/OAuth config, accounts and the marketing/legal pages are gone.
- Server env: `APP_PASSWORD` (blank disables auth, with a warning), `SESSION_SECRET` (blank means a random secret per process, so sessions reset on restart), `DATA_DIR`, `TRUST_PROXY` (default trusts private/loopback proxies such as cloudflared, so `req.secure`/`req.ip` honor `X-Forwarded-*`), `CF_TURN_KEY_ID`/`CF_TURN_API_TOKEN` (optional TURN), `YOUTUBE_API_KEY`, `OPENSUBTITLES_KEY`, `AIOSTREAMS_MANIFEST_URL` (secret, enables `/addon/*`), `SUBTITLE_LANGS` (default `en`), `ROOM_MAX_IDLE_DAYS` (default 60, `0` = never delete inactive rooms). See `server/config.ts`.
- CORS: none in production (same origin). `npm run dev` sets `NODE_ENV=development`, which reflects the request origin with credentials so the Vite dev server on another port can send the session cookie.
- **Deployment** (see `DEPLOY.md`): `compose.yaml` runs `app` (built on the host: `build: .` + `pull_policy: build`, no registry, no published ports, named volume `data` → `/app/data`, 256 MB limit; `docker-entrypoint.sh` starts as root, fixes `/app/data` ownership, then drops to uid 1000 via su-exec), `cloudflared` (tunnel token from `TUNNEL_TOKEN`, public hostname → `http://app:8080`, provides HTTPS) and `backup` (`backup/`: alpine + sqlite3, `.backup` nightly into `backups/` in the same volume, keeps 7) on a project-scoped network. `.github/workflows/docker.yml` only builds the image (amd64, no push) on PRs and `master` to catch Dockerfile breakage. Nothing is published to a registry.
- **Dockerfile**: multi-stage. The build stage runs `vite build` and `npm run buildServer` (`tsc -p server/tsconfig.build.json` → plain JS in `dist-server/`, `.ts` imports rewritten to `.js`). The runtime is `alpine` + the stripped `node` binary copied from `node:24-alpine` (the official image alone is ~175 MB; ours is ~140 MB), prod deps only, uid 1000, tini as PID 1, `HEALTHCHECK` on `/ping`, `NODE_OPTIONS=--max-old-space-size=128 --max-semi-space-size=1`. Running compiled JS saves ~28 MB RSS versus running `.ts` (type stripping loads a wasm transformer). `npm run dev`/`npm start` still run the `.ts` directly; `npm run start:prod` runs `dist-server/`. Keep server code compatible with both (relative `.ts` imports, paths resolved from `process.cwd()` or `import.meta.dirname/..`, which is the repo/app root from both `server/` and `dist-server/`). Files the server reads at runtime (like `words/`) must be copied in the Dockerfile.
- HTTPS is required for camera, mic and screen-share features. To serve TLS directly instead of via the tunnel, set `SSL_KEY_FILE`/`SSL_CRT_FILE`.

## Gotchas

- `AIOSTREAMS_MANIFEST_URL` (in `.env`) embeds the owner's AIOStreams config/debrid credentials. Use it only in `server/addons/aiostreams.ts`. Never send it to the client, log it, put it in error messages, or commit it, and use fake URLs (`https://aio.example.com/...`) in tests. `AddonError` messages are built from fixed strings only, and the addon router's logger runs through `createRedactor`. Stream playback URLs (`/api/v1/debrid/playback/...`) don't contain it, but each carries an encrypted, reusable debrid credential blob, so treat them as room-private too.

- Room passwords: never send `Room.access.password` to a non-owner socket or log it. `REC:roomAccess` is emitted per socket (`emitRoomAccess`), not broadcast. Owner-only socket commands must go through `ownerOnly(...)` in `room.ts`, and new socket tests that exercise them must mark their sockets as owners. Changing `GUEST_COOKIE`'s format or the key derivation logs every guest out (fine, they rejoin with the password).

- Dependabot opens grouped monthly PRs on the fork.
- Socket handlers receive untrusted input. Type params as `unknown` and validate them, following the existing `CMD:*` handlers. Anything that fetches user-supplied URLs must go through `utils/ssrf.ts`.
- Chat lines with `id: ""` have no person (`isPersonlessLine` in `player/formatChat.ts`): `Chat` and `ChatOverlay` render them without a name, avatar or reactions.
- Rooms with no users and 8h of idle time are unloaded from memory and reloaded from SQLite when someone connects (`io.engine.use` in `server.ts`). New room fields must be added to `serialize`/`deserialize` or they'll be lost.
